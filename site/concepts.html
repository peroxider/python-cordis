Five building blocks, one composable kernel.

围绕论文 A Programming Paradigm for Spatiotemporal Composability 的两大原语 —— 可逆效应 与 反应式余效应 —— 落地为五个核心抽象。

§3.1

Revertible Effects · 可逆效应

每一次对 context 的修改都返回一个幂等 disposer,拆卸时按相反顺序执行反向操作。卸载组件 = 完整撤销它的全部副作用。

API含义返回
ctx.register(name, value)绑定一个具名服务dispose
ctx.set(name, value)同 register,并通知依赖它的 fiberdispose
ctx.effect(fn)记录一段拆卸操作dispose
ctx.on(hooks, name, fn)注册一个 hookimpl 监听dispose
 
# paper Algorithm 1 — armed guard
class _Effect:
    def __init__(self, fn): self.fn, self.armed = fn, True

dispose = ctx.effect(fn)
# 调用一次后 armed = False,再次调用是 no-op
dispose()   # 拆
dispose()   # 安全 — 幂等

这就是为什么 fiber.stop() 可以反复调用,也可以在异常路径上安全调用 —— 不会有"二次拆卸"导致的脏状态。

§3.2

Reactive Coeffects · 反应式余效应

组件在 inject 里声明它"需要什么",Fiber 会根据依赖的实际可用性自动 reconcile。

状态触发条件副作用
ACTIVEinject 全部满足apply() 跑过,副作用已注册
INACTIVEinject 缺失未激活,或已拆卸
APPLYING正在跑 apply锁,防重入

关键不变式:

  • 单向: 注册 / 注销服务时,所有声明过该依赖的 fiber 都会被通知。
  • 惰性: 依赖满足时立即激活;依赖消失时立即拆卸 — 不需要手写 watcher。
  • epoch: 每个 refresh() 轮次自增 epoch;陈旧通知被丢弃。
  • 惯性: re-entrant 通知折叠到下一轮,避免栈溢出。
§3.4

Context · 反射式服务容器

Context 既是服务仓库,也是效应边界。它实现论文的 context paradigm:每次变更被记录、可撤销,每次依赖变更被广播给声明它的 fiber。

# 反射式查找 + 父链
ctx.register("fs", FileSystemBackend())    # 在 root 注册

child = ctx.extend()                              # scope 子 context
child.fs                                          # 沿父链找到 root.fs

isolated = ctx.isolate()                       # 论文的隔离 realm
isolated.register("fs", MemBackend())     # shadow 父级同名服务

ctx.use(component) 会创建一个 child context,并把访问权限限制在组件的 inject 声明之内 —— 这就是论文的 proxy-mediated enforcement: 未声明的访问抛 ServiceNotFound。

§3.3

Fiber · 组件运行时实例

Fiber 是 component 的运行时包装:它把一个组件 spec(inject + apply) 绑定到一个 context,并拥有自己的生命周期。

方法语义
fiber.start()手动激活(若依赖不满足则抛错)
fiber.stop()手动拆卸,逆序执行所有 disposer
fiber.refresh()反应式 reconcile,依赖变更自动触发
fiber.dispose()永久卸载,无法再激活

Four hook modes · 四种调用模式

HookRegistry 在 pluggy 之上加了四种调用模式,覆盖大多数插件协作场景。

模式行为典型用途
emit(name, **kw) 每个监听者都被调用,所有结果返回 事件广播、metrics 收集
parallel(name, **kw) 线程池并发调用所有监听者 并行副作用、fan-out
bail(name, **kw) 首个非 None 返回短路(firstresult=True) provider 链、解析器
waterfall(name, **kw) 链式委托,每层可选调用 next 中间件管道、命令链 
@hookspec(firstresult=True)
def resolve_config(key): ...       # → 用 bail 模式

@hookspec
def middleware(req, next): ...    # → 用 waterfall 模式
