Install Python ≥ 3.10

核心包只依赖 pluggy 和 omegaconf,无原生扩展;可选 watchdog 提供文件监听。

# core
pip install python-cordis

# with hot module reload (FileWatcher)
pip install "python-cordis[hmr]"

# for contributors
pip install "-e python-cordis[dev,hmr]"

Define the seam — 内核与插件唯一的耦合点

用 @hookspec 声明扩展点。内核与插件从此只通过 hookspec 对话,内核不知道任何具体插件。

from python_cordis import HookRegistry
from python_cordis.core.hook import hookspec, hookimpl

@hookspec
def on_message(text): ...

Write a plugin — inject + apply

插件只需要两个东西:声明依赖的 inject 元组,和应用副作用的 apply(ctx, ...) 函数。ctx.on 注册监听,ctx.effect 记录拆卸操作 — 都是可逆的。

class Printer:
    name   = "printer"
    inject = ("config",)             # 反应式余效应:依赖满足才激活

    def apply(self, ctx, config):
        @hookimpl
        def on_message(text):
            print(ctx.config["prefix"], text)
        ctx.on(hooks, "on_message", on_message)
        ctx.effect(lambda: print("printer torn down"))

Run a Fiber — 依赖满足即激活

把插件挂在 context 上,ctx.use 会自动 reconcile:inject 满足 → 立即激活;不满足 → 静默待命,直到依赖出现。

hooks = HookRegistry()
hooks.add_spec(__import__(__name__))

ctx = Context()
ctx.register("config", {"prefix": ">"})

fiber = ctx.use(Printer())
assert fiber.active              # True: 依赖已满足

Drive it & tear down — 副作用完整撤销

触发 hook,组件按需响应。停止 fiber 时,所有 effect/on/register 的 disposer 按相反顺序执行,无残留。

hooks.emit("on_message", text="hello, plugins")
# > hello, plugins

fiber.stop()
# printer torn down   ← 自动调用 ctx.effect 注册的 lambda
assert not fiber.active

Bonus — 反应式余效应实战

下面这段直接展示"依赖消失 → 组件自动休眠":把 register 返回的 disposer 调用一下,Fiber 会把 Printer 拆掉;再注册,自动重建。

config_disp = ctx.register("config", {"prefix": ">"})

print(fiber.active)          # True

config_disp()              # 撤销服务 → refresh 触发,fiber 自动 stop()
print(fiber.active)          # False

ctx.register("config", {"prefix": ">"})
print(fiber.active)          # True — 自动恢复
Expected output
> hello, plugins
printer torn down
False
True
